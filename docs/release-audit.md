# v0.1.0 移植監査

## 判定基準

OLD版の数式・アルゴリズム・パーサーは正しい基準として扱う。
新しい実装が想定値に合うことではなく、既存処理と同じ結果を返すことを確認する。
数式の再解釈、PDOSの集計手順変更、入力形式の独自解釈は行わない。
既存のI/F増改築による不整合は、既存の呼び出される処理の契約に合わせて接続する。

## 本体の比較

OLDの実ファイルと実装対応表を用いて904メソッドを比較した。
単独関数に追加したself、クラス化による参照修飾、importと探索パスの移動、
動的ロードのパッケージ名を正規化し、docstringは別に比較する。
getter/setterは名前だけでなくデコレータを区別した。
正規化後890件一致、14件の差分は [全差分](method-differences.txt) に保持した。
これは全入力の動的検証ではない。importの解決とクラス接続は別のテストで検証する。

差分の内容は、bytes/strの元素記号比較、既存生成処理に対する出力配列確保数、
2値/5値の戻り値接続、既存積分DOS属性名、Python 3動的import、
クラス名・型判定の参照先、GUIの旧変換名と戻り値接続である。
新しい物理的期待値へ合わせるための処理変更は含めない。
GUIの改名前後の関係は、元のconv_direct2car.py/conv_car2carABS.pyの履歴コメントにも記載がある。

## 情報の保持

- READMEとCHANGELOGは元の全文を保持し、v0.1.0の説明を別の追記部分に置く。
- コメントはソース中へ復元。クラス内の対応する文・メソッドに配置し、統合したファイルの
  元のヘッダー説明も保持する。改行・配置はクラス化に合わせて変わる。
- 対象342ソースの23,666コメントトークンを個数込みで照合した。
- クラス・メソッドのdocstringはインデントと外側の空白を除いて一致する。
- 元のパッケージ初期化コード・設定・履歴もdocs/historyに資料として保存する。
  これらは実行時にimportしない。
- [移植一覧](migration-inventory.json)は旧パッケージ内の全Pythonファイルとデータの
  配置先・元SHA256を記録する。外側のsamplesもexamples/legacyへ移植した。
- OLD内のbuildとさらに入れ子になったOLDは生成物・旧履歴であり、現行ソースの
  二重移植対象にはしていない。実行実装はOLD直下のsrcを基準とする。

## 今回の取り消し

最初の監査で追加したPDOSの行・集計先・スピン処理の変更と、それを期待値にした
テストは取り消した。同時に追加したgzip・Logger・HiLAPW等への変更もいったん戻し、
今回の移植漏れ修正と混同しないようにした。これらを「OLDのアルゴリズムのバグ」と
する記述、および1,212件成功という旧監査結果は現在の検証結果として採用しない。
未定義名等がOLDにも同じ形であることだけを理由に、処理本体を推測して変更しない。

## 実行検証の範囲

保存済みOLD基準との数値・ファイル比較、クラスの状態保持・引数・戻り値・例外の接続、
既存の接続修正、文書とデータの保持、GUIの単位胞描画呼び出しを検査する。
GUIは描画バックエンドを記録用の代役に置き換えた検査であり、実表示は未検証。
全コマンドやすべての実計算データについて結果一致を確認したという意味ではない。
最終件数とビルド結果は [検証記録](validation.md) に示す。
